# WP2 metadata formats and semantics

2026-11-02. The [native descriptor-only reader](../native/sbmusic/music_metadata.c) replaces no audio/image decoder. It returns the existing full WP1 track DTO, status, warning count and read accounting. A separate bounded helper isolates parsing. The HLS Unicode conversion was factored into [metadata_text.h](../native/common/metadata_text.h); the HLS wrapper retains its original capacity/behavior and regression tests. Now Playing's smaller projections and existing artwork renderer/cache are unchanged.

## Supported subset

| Format | Implemented and tested | Explicit limits |
|---|---|---|
| MP3 | Signature and consecutive MPEG Layer III headers; ID3v1, v2.2/v2.3/v2.4; Latin-1/UTF-16 BOM/UTF-16BE/UTF-8 conversion; title, repeated artists, album/album artist, track/disc plus totals, year/date, genre, compilation; APIC/PIC reference; sample rate/channels/bitrate; Xing/Info/VBRI frame-count duration or bounded CBR estimate | No audio decoding, free-format Layer III, other MPEG layers or exact LAME/gapless delay correction. Maximum tag 256 KiB and audio header search 64 KiB. Compressed v2.2 is unsupported; compressed/encrypted/grouped frames are skipped with warnings. Extended headers and v2.3 tag/v2.4 frame unsynchronization are handled. |
| FLAC | Native signature, required 34-byte first STREAMINFO, sample rate/channels/bit depth/total samples/duration; Vorbis Comments, repeated artist/genre fields, album artist, numbering/date/compilation; PICTURE byte descriptors | 256 metadata blocks, metadata span <=16 MiB and per-read block bound. Padding/unknown blocks skipped without allocation. No FLAC frame validation/decoding or Ogg-FLAC. |
| Ogg Vorbis | Identification/comment/setup markers; CRC-checked header pages, lacing/continued packet assembly, serial/sequence checks; comment fields; sample rate/channels; bounded final EOS/granule duration; METADATA_BLOCK_PICTURE reference | One logical Vorbis stream. Chained/multiplexed/discontinuous headers/tails unsupported when observed; no full-file validation of intervening pages or audio/codebook decode. Header pages/packets and tail reads bounded; duration may remain unknown if a safe EOS is not found. Opus is not advertised. |

ID3 implementation follows the [v2.3 structure](https://id3.org/id3v2.3.0) and [v2.4 structure](https://id3.org/id3v2.4.0-structure); compressed or otherwise unsupported frame transforms never become a guessed raw image range. Unknown ID3v1 extended genre numbers are retained as numeric identifiers instead of being assigned an invented name. The original 80 genre labels are mapped; text genre values remain literal apart from recognized numeric genre notation. Duration frame counts are sanity-bounded against available bytes, but are not a promise of decoded sample-accurate playback time.

FLAC fields and picture/comment layouts are based on [RFC 9639](https://www.rfc-editor.org/rfc/rfc9639.html). Only file-level metadata is implemented. Ogg packet/page boundaries follow [Xiph's framing specification](https://xiph.org/ogg/doc/framing.html); Vorbis header/comment semantics follow [Xiph's Vorbis I specification](https://www.xiph.org/vorbis/doc/Vorbis_I_spec.html). Reading identification/comments does not validate the audio stream or implement decoding. AAC, ALAC, WAV and Opus remain outside WP2.

## Text, records and ambiguity

Full supported fields are retained within WP1 bounds: path 4095 bytes in the DB, title/album 511 bytes, album artist/key 255 bytes, full release date 63 bytes, eight artists at 255 bytes each and eight genres at 127 bytes each. Scanner path access is currently narrower (WP6a combined scope/path <=1023 bytes); exceeding it is explicit incomplete/error, never truncation. Oversized known metadata values fail the probe rather than silently becoming shortened persisted text. Bounded presentation truncation remains a separate UI concern.

The shared HLS conversion replaces invalid Unicode scalars/sequences with U+FFFD and control characters with spaces. UTF-16 BOM is required for encoding 1. No NFC/accent/non-ASCII case normalization is attempted. Filesystem paths must satisfy the existing WP1 UTF-8 validation; unsupported raw-byte names are errors and suppress deletion. Multi-valued comments and ID3v2.4 NUL-separated artist/genre lists are kept as separate values; commas/slashes are not guessed delimiters, preserving names such as AC/DC. Not every historical UTF-16 multi-string/BOM convention or TXXX extension is supported. Unknown formats/keys are not advertised as parsed. Empty values do not erase an earlier nonempty value; contradictory single text/date fields keep the first and report a warning. Numeric numbering/compilation fields use the last nonempty parsed value; dates retain a matching first year/date pair. Missing artist becomes `(Unknown artist)`; missing title uses the filename, and missing album uses WP1's `(Unknown album)` association. Compilation is explicit, not inferred from changing artists. Multidisc numbers/totals are retained; cross-directory album grouping is not guessed without an explicit release key.

Unchanged files reuse their validated indexed metadata and receive only an epoch stamp. A file with malformed/oversized/unsupported required metadata is not silently reindexed as an untagged replacement. Existing committed metadata remains, and that scan cannot sweep missing tracks. A readable untagged supported MP3 is a valid new track with defined fallbacks. Signature sniffing, rather than extension alone, determines codec. Parser warnings identify estimates/ignored extensions; read/structure errors are distinct explicit statuses.

## Artwork references

The scanner discovers descriptors only. Embedded ID3/FLAC direct references carry source-relative offset, length and PNG/JPEG signature type. The owning track supplies source identity and full path; the reference is suffixed with a fingerprint/revision. ID3 unsynchronized data is marked **reparse**, because decoded offsets cannot safely be used as raw file ranges. Vorbis base64 picture comments are also reparse references; they may span Ogg pages and never receive a fabricated contiguous image range.

Common sidecars are checked once per visited directory in deterministic precedence: cover.jpg, folder.jpg, capitalized forms, PNG and JPEG variants. A sidecar reference includes an explicit byte length for its relative path, MIME and bounded stat/content fingerprint; the length avoids delimiter ambiguity in filenames. Embedded artwork takes precedence. Sidecar revisions participate in incremental invalidation. All embedded extents are subtraction-checked against the file; no full image blobs are inserted into SQLite. Signature identification is not full image validation: WP5 must reopen the current source/generation, verify fingerprints and use the existing image workers' decoding/size/security checks. There are no thumbnails, eager cover decoding, new cache directories or new artwork HTTP APIs.

## Resource and dependency boundary

No production TagLib, FFmpeg, libFLAC, libogg, LMS scanner, Perl or decoder dependency is added. Existing vendored SQLite remains pinned; the libc/POSIX process APIs are shared infrastructure. Existing generated CC0 media is reused offline, with deterministic Python metadata fixtures and explicit structural MPEG-header samples. The parser reads at most 768 KiB per file, one 256 KiB tag/block/packet at a time, plus bounded tail/header spans; arbitrary large audio files are never copied into RAM. The exec helper applies address-space/stack/CPU/FD/core limits and reports its own VmHWM where available. Host/QEMU validation does not prove original hardware/driver compatibility.
