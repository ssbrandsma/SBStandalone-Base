# WP3a Base output transport

2026-11-02. [Queue implementation](../native/sbbase/src/output_queue.c), [API](../native/sbbase/include/output_queue.h), integration in [main.c](../native/sbbase/src/main.c).

Before WP3a, send_data repeatedly sent until complete and polled POLLOUT for up to 2000 ms on each EAGAIN, on the single control loop. Multiple partial-progress waits could exceed two seconds overall. Heartbeat bypassed this function with a single unchecked send, potentially losing a partial frame. A stopped reader could delay discovery, other HTTP/Comet clients, alarms and control messages.

All Base TCP sends now pass through the same bounded ordered queue. It first attempts at most 16 KiB with MSG_DONTWAIT|MSG_NOSIGNAL. Unsatisfied bytes go into a lazily allocated 64 KiB buffer per client. Existing queued bytes precede all later bytes, including heartbeat/server-switch frames. No allocation remains after drain/close; maximum aggregate payload storage for 32 clients is 2 MiB, plus small fixed client metadata and allocator overhead. This networking fix applies independently of Standalone Music activation.

Poll requests POLLOUT only while output is pending. Flush performs at most four sends and 16 KiB per client per event-loop pass. EINTR counts toward the syscall limit, EAGAIN/EWOULDBLOCK returns immediately, and writable readiness resumes partial output. Input and output remain serviced for other clients. Existing one-second maximum poll timeout remains; no extra scheduler or worker is introduced.

Queue overflow, allocation failure, send error or a backlog older than 15 seconds closes/revokes the client and frees its queue. Deadline is measured from the beginning of the contiguous backlog and is not refreshed by tiny partial progress. The existing idle checks remain. No subscribed message is silently dropped to keep a slow connection alive; the disconnected client must use its existing Comet reconnect/replay flow. Queue acceptance is not client delivery acknowledgement. Requests that already changed server state retain their normal network-disconnect retry ambiguity; no exactly-once delivery guarantee is invented.

HTTP Connection: close now sets close-after-drain, suppresses new reads and closes after the complete queued response has been sent. Keep-alive response boundaries remain Content-Length. Comet chunk boundaries/order and heartbeat payloads remain unchanged, including under forced partial writes. Request pipelining/legacy envelope extraction are not redesigned; existing input behavior remains. Invalid HELO is rejected separately by the typed parser. Receive EINTR/EAGAIN no longer causes an unnecessary close.

Future Music can bind queue output to connection/owner/stream identity and reject stale enqueues. Scope changes while any bytes are pending are refused: caller must close the originating socket and clear its queue, rather than splice a new frame into a partly written old frame. Raw queue access is reserved for trusted existing generic networking. The conservative controller independently refuses a second stream on the same connection.

Loopback tests use a **host-only LD_PRELOAD shim** to shrink accepted sockets' send buffers, and optionally force 37-byte sends and every third send to EAGAIN. The shim is built only for tests and never packaged. Two peers stop reading, one drains valid HTTP chunks and verifies every update/order, and a fourth request path continues updating metadata. Queue saturation causes observable close, no FD growth, and HTTP close-after-drain still yields complete parseable JSON. Unit socketpairs verify exact bytes, bounded overflow, timed expiry, stale scope and repeated cleanup.

This addresses Base TCP output waits, not all possible control-loop blocking. Existing synchronous catalog/state/alarm persistence, resolver/server-switch validation, stderr logging and unrelated firmware functions remain. UDP discovery sendto stays a single nonblocking bounded datagram; sbproxy and Mongoose web-server I/O are separate unchanged processes. A full nonblocking DNS/filesystem/logging audit is outside WP3a. Host socket pressure and QEMU do not establish old target kernel scheduling or hardware audio performance.
