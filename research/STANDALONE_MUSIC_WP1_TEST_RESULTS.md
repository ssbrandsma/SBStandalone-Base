# Standalone Music WP1 Test Results

Completed 2026-11-02 (work began 2026-11-01). No physical Squeezebox, running device service, mount, TinySC setting or media library was changed. All databases are disposable synthetic host fixtures. No scanner/playback/Jive implementation was added.

## Results

- Pre-WP1 existing baseline: **67/67 passed**, 159.98 seconds.
- Final available CTest suite: **69/69 passed**, 267.18 seconds. Existing tests remain enabled; new tests are `music_library_storage` and `music_library_large`.
- Correctness fixtures: 1k, 10k and 50k tracks; complete bounded-page traversal checks ordering/counts, not just the first page. Artist/album/genre relationships, compilation and multi-disc order are asserted.
- DELETE and explicitly allowed WAL policies passed. Read-only opens/queries passed; writes return read_only. Read-only database hash remains unchanged in the DELETE-policy test.
- Stable identity tested across upsert, rename, delete/reinsert, close/reopen, media offline/new generation, and two distinct sources with identical relative filenames.
- Stale media/library/request IDs, transaction-owner mismatch protection, provider adapter and allocator-limit errors are exercised. Display UTF-8 truncation and full detail retrieval are verified; SQL-like search strings cannot inject statements/wildcards.
- Interrupted process exits with 5k uncommitted inserts and a verified hot rollback-journal magic header; reopening recovers the original exact rows/IDs/titles. This is process-crash recovery, not a physical power-loss durability test.
- Injected Unix VFS write EIO revokes source availability; subsequent queries return offline. The original database reopens with original contents; no automatic rebuild/delete occurs.
- Owned v1 schema migrates atomically to v2 with stable rows/IDs; read-only v1 refuses migration. Newer, foreign and corrupt database copies are rejected and preserve their hashes.
- An external writer lock leaves submit nonblocking and produces bounded worker busy results. Two worker handles observe atomically advanced persisted revisions and reject old query revisions.
- Heap accounting and FD counts remain stable through repeated query/worker-close cycles. SQLite allocator exhaustion returns a native limit result rather than crashing.

## Reproduce

Run serially in WSL/Linux from repository root; existing host HTTP tests share loopback ports. Do not terminate unrelated processes to free those ports.

```sh
CMAKE=/mnt/c/Projects/SBHttpsProxy/build/toolchains/cmake-3.31.8-linux-x86_64/bin/cmake
CTEST=/mnt/c/Projects/SBHttpsProxy/build/toolchains/cmake-3.31.8-linux-x86_64/bin/ctest
"$CMAKE" -S . -B build-dual-tests -DBUILD_SBPROXY=OFF
"$CMAKE" --build build-dual-tests -j4
"$CTEST" --test-dir build-dual-tests --output-on-failure
python3 tests/music/test_library_storage.py build-dual-tests/tests/test_music_library
python3 tests/music/test_library_large.py build-dual-tests/tests/test_music_library
python3 tests/music/benchmark_library.py build-dual-tests/tests/test_music_library --output .local/wp1/performance.json
sh scripts/build-arm.sh all
sh tests/music/cross_contracts.sh
python3 tests/music/test_library_qemu.py
```

Library assertions are explicitly enabled for the CMake test target even in Release builds. Fixtures are generated by the native `fixture()` function, not checked-in database files. Deterministic IDs/paths/relationships derive from track number; timestamps and metadata are fixed. No copyrighted media, live metadata service or physical storage is required.

Address/undefined-behavior sanitizer command:

```sh
gcc -D_FILE_OFFSET_BITS=64 -g -O1 -fsanitize=address,undefined -I native/sbmusic \
  tests/music/test_library.c native/sbmusic/music_library.c native/common/music_contracts.c \
  build-dual-tests/native/sbmusic/libsbmusic_sqlite.a -pthread -ldl -o .local/wp1/library-sanitized
python3 tests/music/test_library_storage.py .local/wp1/library-sanitized
```

This instruments the module/harness; the separately compiled upstream SQLite archive is not sanitizer-instrumented. It is not a full fuzz campaign or thread-sanitizer qualification.

## ARM and gating

Baby ARMv5TE/ARM926 soft-float and Fab4 ARMv6/ARM1136 soft-float normal static builds passed. New isolated archives/harnesses also build for both. WP0 contract/command tests pass under qemu-arm. Native library correctness passes under QEMU for both platforms and both journal modes. These execute against the host kernel/filesystem, not original device kernels or removable FAT/NTFS hardware.

`sbbase` never links/starts the library in WP1. No database or database thread exists in the disabled running product, no new endpoint/listener/menu is exposed, and the old unsupported music commands remain unsupported. Existing Radio/Spotify/Qobuz/Now Playing behavior is covered at the same host/API level as WP0; real sound/handoff and device reboot/storage behavior remain untested. Normal packaging copies its same explicit six binaries, not the isolated `music/` build directory.

The libcurl limitation remains: a current BUILD_SBPROXY=ON configure probe fails with `Could NOT find CURL (missing: CURL_LIBRARY CURL_INCLUDE_DIR)` at native/sbproxy/CMakeLists.txt. Full native host proxy/TLS/HTTP integration tests were not run and are not included in 69 passes. Independent HLS ID3/metadata-wait tests and normal ARM proxy builds do pass. Provide a host libcurl development prefix/package and rerun a separate BUILD_SBPROXY=ON build before claiming that additional coverage.

## Limits of evidence

Unmeasured: actual Baby RAM/headroom, old-kernel execution, FAT/NTFS/FUSE locking/fsync/WAL sidecars, true read-only mounts, slow or physically removed devices, power loss and library operations during real audio. Cancellation is cooperative SQLite VM cancellation; a blocked kernel read cannot be forcibly interrupted. The existing sbbase slow-client output wait is still a WP3a prerequisite and was not refactored here. Tests changing schema/corruption operate exclusively on copies under temporary directories.
