# Standalone Music WP0 Contracts

2026-11-01. Executable definitions: [music_contracts.h](../native/common/music_contracts.h), [pure guards](../native/common/music_contracts.c), [typed command interface](../native/sbbase/include/lms_command.h), [parser](../native/sbbase/src/lms_command.c). No scanner, DB, playlist, transport controller, storage observer, token registry, IPC listener or file server is implemented. Provider function-pointer types are API-only; no implementation is instantiated. Guard functions only validate supplied in-memory values and deduplicate abstract events.

## Identity and lifetime rules

A nonzero 128-bit `sb_music_source_id` identifies a logical physical medium independently of mutable `/media/...` paths. Assignment/UUID collision handling belongs to WP6a; WP0 does not probe hardware or write markers. A nonzero 64-bit media generation identifies one availability interval. Reinserted media retains source ID and increments generation; offline snapshots invalidate every old resource even if the directory still exists. Track identity is source ID plus nonzero indexed track ID. Index assignment and rename preservation belong to WP1/WP2.

Owner, stream, connection, queue and library counters are scoped to a controller incarnation. All start at nonzero values, never wrap/reuse within that incarnation; exhaustion requires invalidation/reinitialization. Restart closes old private connections, discards tokens and pending work, and creates a new random token namespace before requests are admitted. No prior-incarnation queued callback is transferable to the new controller. A future wire message must explicitly carry incarnation identity or be confined to the originating IPC connection. SlimProto does not carry a Base epoch field: WP3a must correlate wire events to connection/stream state rather than pretending a STAT packet includes this token.

`sb_music_media_current` requires matching nonzero source/generation and both snapshots online. Revocation is universal: marking a medium offline or changing its generation invalidates audio, covers and queued worker results. These are contract rules, not a working media manager.

## Physical owner versus metadata lease

Owners are NONE, RADIO, SPOTIFY, QOBUZ and MUSIC. `sb_music_ownership` describes current/requested owner, owner generation, request ID/deadline, connection generation, yield state and explicit physical-release confirmation. Yield states are idle/requested/acknowledged/refused/timeout/revoked.

Future sequence: explicit request -> ask current owner to yield -> stop producer/restore firmware hooks -> physical acknowledgement -> confirm player connection -> commit new generation. `sb_music_yield_ack` rejects stale request/owner/connection IDs, duplicates and expired acknowledgements. Refusal and timeout cannot commit; `sb_music_can_commit_owner` additionally requires positive release confirmation and a live deadline. Reconnect must issue a new connection generation and fresh yield request; revocation must clear confirmation and cancel pending work. WP0 supplies guards, not request scheduling, transport stops, app adapters or generation allocation.

The existing `np_api` claim/update/heartbeat/release contract remains intact. A successful claim changes only metadata ownership. The contract test actually claims a Music metadata lease while the physical-owner record remains RADIO and cannot commit without yield. No production path connects these new guards to np_manager. Existing Radio/Spotify/Qobuz takeover behavior therefore remains unchanged. Radio's external-library handoff excludes loopback; Qobuz disconnects SlimProto; Spotify user-control flags remain false. Those are future adapter requirements, not fixed by WP0.

## Stream, terminal events and queue

`sb_music_stream_id` binds epoch, owner/media/connection generations and stable track identity. `sb_music_stream_guard` rejects nonmatching IDs, duplicate event flags and any event after the first terminal result. Connected, decoder-ready, audible, input EOF, drained, stopped and failed are distinct. Ready and EOF are not terminal. Independent flags retain readiness/EOF even when audible state is current. Drained/stopped/failed are terminal for this guard. WP3a must decide when a raw STAT/DSCO event really means a contextual terminal result; this guard does not interpret packets, sequence codecs or advance tracks.

A queue entry has a stable entry ID, track identity and media generation. Snapshots have revision, owner/media generations, count/current index, current entry and track. `UINT32_MAX` means no current index. The policy maximum is 10000 entries, not an allocation of 10000 entries. A future update compares expected revision and owner/media generations, validates every selection, then commits exactly once. `sb_music_queue_update_valid` only guards the update envelope, result-count policy and revision exhaustion; it does not implement ordering, index selection, persistence or an atomic storage mechanism. Initial revision is 1; no revision wraps.

## Database-neutral queries

Artists/albums/tracks/genres/folders/playlists use typed query kind, sort enum, stable filter IDs, bounded search string, source availability/generation, library revision and offset/limit. A zero library revision means caller accepts the current snapshot; a nonzero revision must be checked by the future provider. `sb_music_query_valid` validates structure/availability/bounds, not whether filter IDs exist.

Maximum page request: 50 rows; DTO byte budget: 16384. `sb_music_row` is a bounded display projection (128-byte name/secondary fields), never the full database model or filesystem path. Full metadata remains in the future DB. The test verifies a maximum fixed-row page fits its DTO budget. Serialized JSON can expand and is separately bounded by the existing response buffer: future serializers must cap/return a defined error rather than truncate JSON. No Jive actions or JSON fields belong in the database DTO. The provider submit/cancel interface is API-only; completions must be immutable, scoped to request/library/media generations and transferred to the control loop through a bounded wakeup queue. No SQL or blocking wait is allowed in a protocol callback.

## Private HTTP resource capability

The resource contract is shared native data, not a new public endpoint. Proposed transport: private AF_UNIX socket owned by Base under a restrictive runtime directory, with peer credentials checked against the expected service identity. Maximum control frame 4096 bytes, one descriptor per successful open, at most eight live resources/pending opens initially; no path or untrusted pointer appears in a wire frame. Serialize explicit widths/endian/version rather than memcpy a C struct with padding. Define cancellation, request IDs and connection incarnation in the later wire implementation.

Token policy: 32 cryptographically random bytes, opaque encoded representation, generated by the controller; never reuse the existing predictable Comet client-ID helper. Tokens are not paths, track IDs or persistent secrets. Compare without timing leaks where appropriate, do not log complete tokens, and expire by monotonic time. Artwork binds media generation; audio additionally binds owner generation and stream epoch. A token must be current at admission and rechecked on every worker completion/read chunk. No absolute path or `file://` input is accepted from HTTP clients.

A validated controller open anchors traversal at a trusted root, disallows symlink escapes/special files and verifies regular-file identity after open. Successful provider completion transfers one owned descriptor to the web process; sender and receiver each close their own reference on every exit path. `sb_music_resource_handle` expresses this ownership, but WP0 never opens music files. Descriptor passing duplicates an open-file description and can share its offset: concurrent consumers must use `pread` with independent 64-bit positions, not `lseek/read` on a shared offset.

Allowed methods are GET/HEAD only, normalized single byte ranges with overflow-safe first/length, known exact size and allowlisted MIME. Future HTTP range parser must handle closed/open-ended/suffix ranges, empty files, 206/416, Content-Range/Length and >2 GiB offsets; multipart ranges are explicitly unsupported initially. `sb_music_range_valid` validates a normalized nonempty range without addition overflow, not an HTTP header. HEAD produces the corresponding headers without audio reads. No transcoding.

Proposed error mapping: invalid token 404; known expired/revoked token 410; disallowed method 405; invalid range 416; unavailable media/busy backend 503; unexpected I/O before headers 500/503. Ownership/generation mismatches revoke rather than serving stale bytes. Once headers are sent, cancellation/removal/I/O failure closes the transfer; never emit another HTTP response inside an audio body. Cancellation is idempotent, closes owned descriptors and suppresses late completions. Eject waits for quiescence acknowledgement; forced removal cannot wait for a callback. An already open fd does not authorize continued reads after revocation.

The host socketpair test passes SCM_RIGHTS descriptors 100 times, applies explicit FD_CLOEXEC and checks FD counts. Linux documents [descriptor passing and AF_UNIX](https://man7.org/linux/man-pages/man7/unix.7.html); this is technically practical for Linux 2.6-era systems, but actual target-kernel behavior and service permissions remain pending. Avoid requiring newer MSG_CMSG_CLOEXEC/openat2/pidfd APIs. Existing Mongoose mg_fs can host a provider, but its pathname-open API, shared offsets, size_t counters and synchronous static reads are not a finished fit. WP0 does not modify Mongoose or implement production IPC.

## Feature gate and execution boundaries

`SB_MUSIC_ENABLED` is 0. CMake `SB_ENABLE_MUSIC` defaults OFF and deliberately rejects ON because there is no runtime implementation yet. Normal packaging remains unchanged; candidate libraries live only in ignored spike builds. Contracts use fixed structures and pure checks: no heap allocation, files, listeners, worker threads or services. Mutable guard state belongs to one future controller loop; workers return immutable results, never mutate guards concurrently. These functions are not thread-safe shared state containers. WP0 adds exact command classification independently of future music activation; all unimplemented music commands return unsupported and advertise no capability/menu.
