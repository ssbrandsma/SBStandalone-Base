# Standalone VPN implementation

Secure portal update (16 November 2026): normal profile provisioning now uses paired HTTPS; SSH is advanced recovery only. See [HTTPS delivery and remaining physical acceptance](TLS_DELIVERY.md) and the [secure portal guide](SECURE_WEB_PORTAL.md). Historical SSH-only notes below are superseded by that update.


## Repository investigation and architecture

Investigation found no existing VPN controller, profile importer, TUN manager or owned firewall layer. The existing C services, paired Mongoose portal, asynchronous Jive HTTP client and Lua service supervisor are extended directly. Platform.lua remains the platform authority for the applet; the ARM manager independently checks the same known Baby/Fab4 board identities. Existing music changes are preserved. No AGENTS.md applied.

`native/sbvpn` is the sole VPN policy/process/network owner. It is an optional fourth service appended after the original three services in `defaultServices()`, preserving their indices. Old packages without the executable/module continue to work. Manager errors do not stop sbbase, sbproxy or sbwebserver. The existing Jive supervisor handles manager restart and backoff; there is no second daemon supervisor. OpenVPN is a direct child, runs at reduced priority, and receives a parent-death signal. Recovery validates PID, start ticks and executable device/inode before signaling anything. No `killall`, user-built shell command or audio ownership change is introduced.

`vpn_http.c` bridges up to four in-flight requests over private Unix SOCK_SEQPACKET, with bounded messages and ten-second timeouts; it does not synchronously wait for OpenVPN. The manager and clients check Unix peer credentials. Managed OpenVPN hooks additionally require their caller to be a child of the exact owned OpenVPN process. The private management socket checks the exact OpenVPN child PID and UID. Raw management strings never become API fields.

The web VPN tab and `applet/Vpn.lua` consume this shared state. Jive uses the existing loopback remote.capability authentication, async RequestHttp, five-second polling while open and timer cleanup. Browser polling stops on navigation. CONNECTED requires management success, an authenticated up hook and successful interface/routes/DNS application. States include DISABLED, UNAVAILABLE, DISCONNECTED, CONNECTING, CONNECTED, SWITCHING, RECONNECTING, DISCONNECTING and ERROR. The manager publishes `network_ready_generation`; no new cross-applet event consumer is implemented. Existing Radio reconnect/watchdog behavior remains responsible for stream recovery; hardware audio validation is pending.

## Authentication and API

Public endpoints below use `/api/vpn`; the native frontend uses `/api/internal/vpn` and the existing loopback capability gate. Browser access requires pairing. Mutations require same-origin checks and respect management read-only mode. Profile mutations require an IPv4 loopback browser connection through an SSH forward, in addition to pairing. LAN HTTP returns 426. No TLS termination or trusted forwarding-header bypass is added. Native profile provisioning is forbidden. A stored-profile structural validation POST is allowed from a paired LAN browser.

| Method | Path | Behavior |
| --- | --- | --- |
| GET | /capabilities | Measured runtime support and reasons |
| POST | /capabilities/refresh | Reprobe while disconnected |
| GET, PUT | /settings | Startup, reconnect, DNS, fallback DNS, kill switch, selection, optional country_verify |
| GET, POST | /profiles | Redacted metadata list / secure import |
| GET, PUT, DELETE | /profiles/ID | Redacted metadata / secure edit / secure delete |
| POST | /profiles/ID/validate | Structural validation, not server authentication |
| GET | /status | Actual state, owned protections, sanitized error and generation |
| GET | /logs | Bounded sanitized state/error events |
| POST | /connect | Select optional profile_id and request connection/switch |
| POST | /disconnect | Remove requested VPN state and owned protection |
| POST | /reconnect | Explicit retry even when automatic reconnect is disabled |
| POST | /test | Rate-limited optional public IPv4 check |

Private `/event` hooks are never exposed through HTTP. Strict JSON checks reject duplicate/escaped keys, embedded NUL, excess nesting, wrong types and unknown request fields. IDs are 32 lowercase random hex characters. Connect replies 202, not a fabricated successful connection. Profile edits/deletes are rejected while active/requested. Secret GET/export operations do not exist. Username, password, config text and inline keys are absent from status/list/log responses.

## Storage and import

Persistent root: `/mnt/storage/standalonebase/vpn`; runtime root: `/tmp/standalonebase/vpn`. Directories are 0700, files 0600. The measured root-owned `/mnt/storage/standalonebase -> /etc/standalonebase` alias is recognized narrowly, with both physical ancestor trees checked; other symlinks remain rejected. Trusted ancestors, no symlink following, owner validation, descriptor-relative opens, private atomic temporary files, fsync + rename + directory fsync protect writes. Profiles are schema-versioned JSON with random-ID filenames; settings and runtime session/process/network journals are separate. Future schema/corrupt settings, including invalid persisted types, are retained, disable connection, and report an error. Unreadable existing network journals are invalid, not treated as absent. Invalid recovery records are retained, with no global network reset. At most 16 profiles, 49,152 bytes of imported configuration, 2,048 bytes per line and eight remote entries are supported. Large writes reserve an additional 1 MiB free space. Last-success timestamps persist at most hourly to reduce flash writes. Ordinary backup allowlists exclude VPN secrets.

The allowlist accepts client/TUN, IPv4 UDP or TCP-client remotes, remote-cert-tls server, verify-x509-name, TLS minimum 1.2/1.3, modern explicitly permitted ciphers/digests, key-direction, auth-user-pass without a file path, and inline ca/cert/key/tls-auth/tls-crypt. Certificates and private keys must be paired when supplied. Certificate parsing/chain verification is performed by OpenVPN at connection; structural validation does not claim cryptographic validity. TLS minimum 1.3 is preserved. No crypto downgrade is attempted.

Supported compatibility directives include nobind, persist-key, persist-tun, remote-random, auth-nocache, bounded resolv-retry, verb, pull, ping-timer-rem, fast-io, ping/ping-restart/ping-exit, connect-timeout, keepalive, auth-retry, tun-mtu-extra, tun-mtu, mssfix, reneg-sec, explicit-exit-notify and allow-compression no. Some are normalized or overridden by manager policy. The parser is authoritative; unsupported directives fail with their name. It rejects scripts, plugins, includes, external file paths, TAP/server mode, logging/status/management overrides, proxies, arbitrary route directives, compression, insecure crypto, encrypted private keys and unrecognized inline sections. Separate certificate upload, IPv6 remote transport, provider extensions and interactive MFA are not implemented.

Password operations are explicit keep/replace/clear. Blank browser edits preserve existing values. Runtime credentials live in a private file, never argv. Core dumps are disabled in the manager and HTTP server, and secret buffers are wiped where ownership allows. Root and the browser executing the provisioning page remain trusted; storage permissions are not encryption at rest. OpenVPN output is consumed privately and classified into fixed errors, never copied into public diagnostics. A bounded 16-event ring avoids raw provider/user material.

## Runtime networking

Capability checks inspect model, actual OpenVPN path/version, root/CAP_NET_ADMIN, the 10:200 TUN device and open permission, IPv6/firewall query support, safe resolver replacement and IPv4 forwarding. Unsupported optional VPN leaves Base running. OpenVPN compile-time management/TLS support is ultimately confirmed when starting the real connection, not fully exercised by the read-only probe. Helpers are fixed executable paths with structured argv and bounded waits. No desktop ip/nmcli dependency exists in the manager.

The manager generates its own config, management and up/down hooks. `ifconfig-noexec` and `route-noexec` let it validate conflicts before assigning the dedicated sbvpn0 address. A nonexecuted dummy route causes OpenVPN to populate route_vpn_gateway for the authenticated hook. Server-pushed arbitrary routes do not execute.

Native ioctl and rtnetlink configure the interface and routes. Owned routes use protocol 186 and metric 32760: endpoint /32 through its actual physical interface/gateway, two full-tunnel /1 routes, physical multicast 224/4 and link-local 169.254/16, and DNS /32 routes through the VPN. Actual connected LAN prefixes remain local (up to eight); no blanket RFC1918 bypass is added. IPv4 policy rules outside standard local/main/default and pre-existing public-specific routes cause an explicit conflict. Unrelated blackhole routes remain untouched. IPv4 forwarding is rejected. Connected interface/address/prefix changes and missing/changed owned routes are monitored every three seconds and trigger controlled reconnect.

Isolated SBVPN4A/B and SBVPN6A/B OUTPUT chains use inactive-chain construction followed by inserting the new jump before removing the old one. A reachable chain is never flushed. Existing unrelated rules are respected using RETURN, not a blanket ACCEPT. No established-connection bypass precedes the kill policy. DNS port 53 is blocked before LAN allowance when VPN DNS is enabled. Public IPv6 is blocked while requested, retaining actual connected prefixes, link-local and local multicast. No IPv6 tunnel is advertised. Missing required IPv6 protection makes VPN unavailable. Kill-switch status is true only when all required families have installed protection.

The kill switch requires literal IPv4 remotes and VPN DNS. Hostname bootstrap exceptions are intentionally unsupported. A connection failure or automatic retry retains requested state and protection; explicit Disconnect removes protection. Initial DNS lookup without kill switch can use the physical resolver. Guard installation is journaled first, and partial-install failure retains an existing valid chain. Runtime recovery reads actual jumps and removes only owned inactive state. Protection starts after Jive starts; boot-time leak protection is explicitly false.

DNS targets a root-owned regular resolver or trusted symlink target using atomic replacement, preserving the symlink. The network journal stores original and owned resolver contents. DHCP replacement is detected, the newer non-VPN contents become the restoration snapshot, and VPN DNS is reapplied. Cleanup restores only when current contents still match the manager's owned value. Pushed DNS must be valid non-LAN IPv4, with deduplication; absent DNS requires an explicit fallback or fails. Different firmware resolver managers require hardware acceptance.

Transient failures retry with 2..64 second backoff (DNS failures wait 30 seconds); authentication failures stop until explicit action. OpenVPN and manager crash recovery is tested. Explicit reconnect/profile switch works with auto reconnect disabled. --recover handles both live IPC and locked offline journal recovery, removes only owned state and disables startup.

## Public verification and limits

Optional public IP verification uses the existing sbproxy's TLS-validating HTTPS request to api.ipify.org, an existing public-address policy, eight-second/4 KiB bounds, connection-generation tracking, and sixty-second rate limiting. No curl subprocess or shell is used. A failed lookup does not change tunnel truth. Configured country is never verified implicitly. Optional `country_verify` defaults false and adds a bound request to `https://ipwho.is/CHECKED_IP?fields=success,ip,country_code`, using the same proxy and bounds. Only success=true, an exact matching IP and a two-character uppercase country code are accepted. Requests are limited to one per hour per manager lifetime, with in-memory cache reuse only for the same IP. Disabled, failed, throttled or mismatched responses stay Unknown without changing connectivity; disabling clears displayed country. No account/profile/device ID or credential is sent, and the UI discloses public-IP logging. The host integration mocks these proxy contracts; it does not claim real public Internet or geographic verification. See the [readiness review](VPN_READINESS_REVIEW.md) for provider terms and HTTPS architecture research.

No throughput, audio continuity, discovery or device memory claims are made from host tests. Existing playback and radio ownership paths were not changed. Production approval needs both target devices, a compatible firmware/runtime, controlled public VPN acceptance and the tests in the [delivery report](VPN_DELIVERY.md).

Reference: [OpenVPN 2.5 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-5-manual/), consulted 2026-11-15. The profile language is treated as executable policy rather than arbitrary data.

The demonstrated public-IP defect was the proxy request path: `/https/api.ipify.org` returned HTTP 400 on the actual Baby, while `/https/api.ipify.org/` returned HTTP 200 through the same TLS-validating proxy. Before VPN, the checked address was 62.45.37.138; a US tunnel changed egress to 149.22.84.136 in the initial investigation. The final manager automatically verified US 149.22.84.138, with ipwho.is reporting United States / California / San Jose. An explicit NL switch invalidated the US data immediately, reset the accounting interval, and verified 185.132.133.153 / NL / Provincie Zuid-Holland / Gemeente Westland. These provider locations are approximate, not physical server-location guarantees. DNS and HTTPS requests succeeded with VPN DNS active. Verification errors are separate from tunnel state.

The manager collects four owned `sbvpn0` counters directly from sysfs. These files exist on this Baby. `/proc/net/dev` is the bounded fallback, selected once per tunnel attachment; sources are never mixed during that attachment. Interface index checks detect recreation. Linux 2.6.26 `net_device_stats` uses unsigned long, so this 32-bit ARM target uses 32-bit underlying wrap handling with uint64 accumulation. Actual rollover was not forced on hardware. The kernel-version prefix check was corrected during live validation; the final Baby reports `counter_bits: 32`. Modern hosts use 64-bit counters. Near-boundary wraps accumulate; other decreases or recreated interfaces establish a new baseline with zero rate to avoid spikes. Missing samples mark telemetry unavailable; resumption retains totals without a misleading instantaneous rate. Some traffic during teardown or an unobserved reset cannot be recovered.

Sampling uses the existing manager loop at two-second monotonic intervals. Rates divide counter deltas by actual elapsed time. Explicit Connect/profile switch/manual Reconnect reset accounting; automatic retries retain the requested session. Disconnect freezes totals and zeroes rates. Manager restart starts an explicitly labeled memory-only interval. No additional daemon, per-sample subprocess, persistent traffic log or history buffer was added. The additive status fields preserve existing clients. The dashboard has four compact cards, decimal units, manual IP refresh, local duration ticks and focus-preserving two-second updates.

Geolocation remains opt-in. An eight-entry, one-hour per-IP cache and a global minimum 60 seconds between location attempts bound external requests. Responses require success, a matching independently verified IP and valid country code; absent/null optional region/city remain empty. A queued lookup handles a new tunnel within the cooldown. Disable cancels the lookup and clears displayed location. The original opt-out setting was restored after acceptance.
